# ESP32-S3 智能语音助手硬件设计与交付文档

**项目名称：** ESP32-S3 智能语音助手
**主控平台：** ESP32-S3 N16R8
**开发环境：** ESP-IDF 5.3.3
**文档版本：** V1.1
**交付日期：** 2026年11月22日

# 一、项目概述

## 1.1 项目背景

本项目设计并实现了一套基于 ESP32-S3 的嵌入式智能语音助手。系统结合本地语音识别前端、实体按键交互、云端语音识别及智能对话服务，实现从语音唤醒到云端问答再到文本显示的完整交互流程。

系统采用 ESP32-S3 作为主控制器，负责麦克风音频采集、本地唤醒词检测、语音活动检测、音频录制、数据封装、网络通信及 LCD 显示。云端服务器负责语音转文字、智能体对话处理，并将回答返回给设备。

与完全依赖云端的语音交互方式不同，本项目将唤醒检测和语音活动检测放在设备本地执行，减少不必要的网络请求，同时利用按键确认机制降低环境背景人声对交互过程的干扰。

## 1.2 系统主要功能

1. **本地语音唤醒：** 使用 ESP-SR WakeNet 实现唤醒词“你好小智”的本地检测。
2. **按键交互控制：** 唤醒后等待用户按下实体按键，确认开始新一轮语音交互。
3. **本地语音活动检测：** 使用 ESP-SR VAD 判断当前音频是否包含有效人声。
4. **自动语音录制：** 检测到人声后开始录音，根据连续静音时长判断录音结束。
5. **音频数据封装：** 将采集的 PCM 数据封装为标准 WAV 文件。
6. **云端语音交互：** 通过 Wi-Fi 和 HTTPS 上传 WAV 音频，调用云端 ASR 和 Agent 服务。
7. **文本回答显示：** 解析服务器返回的回答文本，并通过 LCD 显示。
8. **连续交互：** 当前唤醒会话中，用户可以通过再次按键发起下一轮语音交互。

# 三、硬件连接设计

## 3.1 INMP441 麦克风模块

麦克风采用 I2S 数字音频接口与 ESP32-S3 连接，使用 I2S0 接收音频数据。

| INMP441 引脚 | ESP32-S3 GPIO  | 说明           |
| ------------ | -------------- | -------------- |
| SCK          | GPIO5          | I2S 时钟 BCLK  |
| WS           | GPIO4          | I2S 帧同步信号 |
| SD           | GPIO6          | 音频数据输入   |
| VDD          | 3.3V           | 电源           |
| GND          | GND            | 地线           |
| L/R          | 按实际配置连接 | 声道选择       |

音频采集参数：

- 采样率：16000 Hz
- I2S 数据槽位：32 bit
- 声道：Mono
- PCM 数据位宽：16 bit

麦克风输出的 I2S 数据以 32 位格式读取，程序通过移位操作提取有效音频数据，转换为 16 位 PCM：

```
int16_t pcm = (int16_t)(mic_buffer[i] >> 16);
```

## 3.2 MAX98357A 音频功放模块

功放模块通过 I2S1 接收 ESP32-S3 输出的数字音频数据。

| MAX98357A 引脚 | ESP32-S3 GPIO  | 说明         |
| -------------- | -------------- | ------------ |
| BCLK           | GPIO15         | I2S 时钟     |
| LRC / WS       | GPIO16         | I2S 帧同步   |
| DIN            | GPIO7          | 音频数据输出 |
| VIN            | 按模块规格供电 | 功放电源     |
| GND            | GND            | 地线         |

音频输出参数：

- 采样率：16000 Hz
- 数据位宽：16 bit
- 声道：Stereo

当前版本暂不启用云端 TTS 音频播放，功放模块保留用于后续音频播报功能扩展。

## 3.3 独立按键

独立按键连接 ESP32-S3 GPIO9，用于唤醒后的交互确认。

| 按键连接端 | ESP32-S3 GPIO | 说明     |
| ---------- | ------------- | -------- |
| 按键一端   | GPIO9         | 按键输入 |
| 按键另一端 | GND           | 接地     |

GPIO 配置：

- 工作模式：GPIO 输入模式
- 内部上拉：使能
- 内部下拉：关闭
- 按键松开：高电平
- 按键按下：低电平

按键采用轮询方式检测，通过约 20 ms 的软件延时进行消抖。检测到按键按下后，按键任务通过二值信号量通知语音录制任务。

### 3.4.4 **工作原理**

ESP32-S3 通过 SPI 总线向 LCD 发送显示数据和控制命令。其中，SCL 提供 SPI 时钟，MOSI 负责向显示屏发送数据，CS 用于选择显示设备，DC 用于区分命令和显示数据，RST 用于复位显示屏，BLK 用于控制屏幕背光。

系统运行过程中，ESP32-S3 根据语音交互状态更新 LCD 显示内容。当本地 WakeNet 检测到唤醒词后，屏幕显示唤醒提示；录音、上传及等待云端响应期间显示对应状态；收到服务器返回的 JSON 数据后，提取其中的 `answer` 字段并显示文本回答。

# 四、系统设计原理

## 4.1 总体设计思想

系统采用“本地音频前端处理 + 云端智能语音服务”的设计方式。

本地处理主要负责实时性较高、需要持续执行的音频检测任务；云端处理主要负责计算量较大、模型资源需求较高的语音识别和智能对话任务。

这种设计能够降低 ESP32-S3 的计算负担，同时利用云端模型实现更加复杂的自然语言理解和回答生成。

系统主要划分为以下五个功能模块：

1. 音频采集模块
2. 本地语音检测模块
3. 录音与音频封装模块
4. 网络通信与云端交互模块
5. LCD 显示与按键控制模块

## 4.2 音频采集原理

系统使用 INMP441 数字麦克风采集环境声音。

INMP441 通过 I2S 接口向 ESP32-S3 发送数字音频数据。ESP32-S3 配置为 I2S 主机，提供 BCLK 和 WS 时钟信号，并通过数据输入引脚接收音频。

采集得到的音频数据首先以 32 bit 格式存储，随后提取有效的高位数据，转换成 16 bit PCM 格式，供 WakeNet、VAD 和 WAV 封装模块使用。

采用 16 kHz 采样率，能够满足当前语音唤醒、语音活动检测和云端语音识别的输入要求。

## 4.3 本地语音唤醒原理

系统使用 ESP-SR 提供的 WakeNet 模型实现本地唤醒。

设备启动后，麦克风持续采集音频，唤醒任务按照 WakeNet 所需的音频帧长度组织数据，并输入模型进行关键词检测。

当前每帧包含 512 个采样点，在 16 kHz 采样率下对应 32 ms。

当 WakeNet 检测到预设唤醒词“你好小智”时，程序设置 `AUDIO_WAKEUP_BIT` 事件位，通知语音录制任务进入唤醒交互状态。

本地唤醒不需要将持续采集的音频实时上传至服务器，能够减少网络传输和不必要的云端处理。

## 4.4 按键确认原理

考虑到实际使用环境中可能存在其他人的说话声，仅依靠 VAD 判断是否开始录音，容易受到背景人声干扰。

因此，系统增加 GPIO9 独立按键作为人工确认机制。

按键任务持续检测 GPIO9 电平，检测到按键按下后，通过 FreeRTOS 二值信号量 `xSpeekSemphore` 通知语音录制任务。

语音录制任务必须同时满足以下两个条件，才会开始 VAD 检测：

1. WakeNet 已经检测到唤醒词。
2. 用户按下实体按键。

按键确认机制将唤醒操作与录音启动分离，避免唤醒后环境中的背景人声直接触发录音。

## 4.5 VAD 语音活动检测原理

系统采用 ESP-SR 提供的 VAD 模块检测当前音频帧是否包含人声。

VAD 将输入音频分为连续的数据帧，判断每帧属于语音还是静音状态。

当前配置为：

- 采样率：16000 Hz
- 每帧采样点：480
- 每帧时长：30 ms
- VAD 模式：VAD_MODE_1

程序根据 VAD 返回的状态判断是否开始录音。

为了降低短暂噪声造成的误触发，系统要求连续多帧被判断为人声后才开始录音。

录音过程中，程序持续检测语音状态。当连续静音时间达到设定阈值时，结束本轮录音。

当前连续静音结束阈值为 800 ms，最大录音时间为 8000 ms。

需要说明的是，VAD 负责判断是否存在语音特征，并不具备说话人身份识别能力。因此，按键确认机制仍然是减少背景人声误触发的重要手段。

## 4.6 PCM 与 WAV 音频封装原理

麦克风采集并处理后的音频数据为 PCM 格式。PCM 只保存连续的音频采样数据，不包含完整的音频文件描述信息。

为了方便服务器接收和处理，系统需要将 PCM 数据封装成标准 WAV 文件。

WAV 文件主要由两部分组成：

1. WAV 文件头：描述音频格式、采样率、声道数、位宽和数据长度。
2. PCM 音频数据：保存实际录制的声音采样数据。

当前 WAV 参数：

| 参数       | 配置     |
| ---------- | -------- |
| 音频格式   | PCM      |
| 采样率     | 16000 Hz |
| 声道数     | 1        |
| 位宽       | 16 bit   |
| 文件头长度 | 44 bytes |

程序首先根据录音样本数量计算 WAV 文件大小，然后写入标准 RIFF/WAVE 文件头，最后将 PCM 数据复制到文件头之后，形成完整的 WAV 数据缓冲区。

## 4.7 云端智能语音处理原理

ESP32-S3 负责完成音频采集和本地语音前端处理，语音识别和自然语言理解由云端服务器完成。

设备通过 HTTPS 将 WAV 文件上传至语音接口。

服务器收到音频后，依次执行：

1. ASR：将用户语音转换为文本。
2. Agent：将识别出的文本交给现有智能体进行理解和回答。
3. TTS：按照后端接口设计生成语音音频。

当前设备主要使用服务器返回的 JSON 元数据中的 `answer` 字段，将文本回答显示在 LCD 上。TTS 音频播放暂不启用。

# 五、通信数据流设计

## 5.1 系统内部事件通信

系统使用 FreeRTOS 多任务机制，将唤醒检测、按键检测和录音处理分离。

| 任务                | 主要职责                                  | 通信机制               |
| ------------------- | ----------------------------------------- | ---------------------- |
| `waked_task`        | 读取麦克风、执行 WakeNet                  | Event Group            |
| `key_task`          | 轮询按键、检测按下事件                    | Binary Semaphore       |
| `audio_record_task` | 等待唤醒、按键确认、VAD、录音、上传和显示 | Event Group、Semaphore |

主要事件和信号量：

| 名称                    | 类型             | 作用                               |
| ----------------------- | ---------------- | ---------------------------------- |
| `AUDIO_WAKEUP_BIT`      | Event Group Bit  | WakeNet 唤醒后通知录音任务         |
| `AUDIO_RECORD_DONE_BIT` | Event Group Bit  | 录音任务结束后通知唤醒任务恢复检测 |
| `xSpeekSemphore`        | Binary Semaphore | 按键按下后通知录音任务             |

内部事件数据流：

WakeNet 检测到唤醒词
→ 设置 `AUDIO_WAKEUP_BIT`
→ `audio_record_task` 收到唤醒通知
→ 等待 `xSpeekSemphore`
→ 按键任务检测到按下并释放信号量
→ `audio_record_task` 开始 VAD 检测和录音。

当前唤醒任务在收到唤醒事件后，会等待 `AUDIO_RECORD_DONE_BIT`，避免在录音任务占用麦克风期间继续执行 WakeNet 检测。

## 5.2 音频数据流

音频数据的完整流转过程如下：

INMP441 麦克风
→ I2S0 接收 32 bit 音频数据
→ 转换为 16 bit PCM
→ WakeNet 本地唤醒检测
→ 按键确认
→ VAD 检测
→ 录制 PCM 音频
→ WAV 文件封装
→ HTTPS 上传。

录音数据保存在 ESP32-S3 的 PSRAM 中，减少较大音频缓冲区对内部 RAM 的占用。

## 5.3 云端网络通信流程

设备通过 Wi-Fi 接入互联网，使用 HTTPS 与云端语音接口通信。

**请求接口：**

```
POST https://weather-travel-assisant-o9c4j.ondigitalocean.app/api/voice/chat
```

请求格式：`multipart/form-data`

主要字段：

| 字段        | 类型     | 说明                   |
| ----------- | -------- | ---------------------- |
| `sessionId` | String   | 会话标识，用于关联对话 |
| `file`      | WAV 文件 | 本轮录制的语音数据     |

音频文件参数：

- 文件名：`record.wav`
- 音频编码：PCM
- 采样率：16000 Hz
- 位宽：16 bit
- 声道：Mono

ESP32-S3 将 WAV 数据按照 HTTP multipart 格式组织，通过 HTTPS 分块上传至服务器。

## 5.4 服务器处理与响应数据流

服务器接收到设备上传的 WAV 文件后，按照以下流程处理：

WAV 音频
→ ASR 语音识别
→ 得到用户问题文本
→ Agent 智能体处理
→ 生成回答文本
→ TTS 音频生成
→ 返回 multipart/mixed 响应。

响应中包含 JSON 元数据和音频数据。

JSON 元数据主要包含：

| 字段           | 说明                   |
| -------------- | ---------------------- |
| `question`     | ASR 识别得到的用户问题 |
| `answer`       | Agent 生成的回答       |
| `sessionId`    | 当前会话标识           |
| `hasAudio`     | 是否包含音频结果       |
| `errorMessage` | 错误信息               |

当前 ESP32-S3 固件解析 JSON 中的 `answer` 字段，并通过 LCD 显示回答文本。

# 六、系统运行流程

系统完整运行流程如下：

1. ESP32-S3 上电，初始化 GPIO、I2S、LCD、WakeNet、VAD 和 Wi-Fi。
2. 麦克风持续采集音频，WakeNet 执行本地唤醒检测。
3. 检测到“你好小智”后，通知录音任务。
4. LCD 显示“小智已唤醒，请按键”。
5. 用户按下按键，开始 VAD 检测。
6. VAD 检测到连续有效人声后开始录音。
7. 用户说完后，VAD 根据连续静音时间判断录音结束。
8. 将录音 PCM 数据封装为 WAV。
9. 通过 HTTPS 上传 WAV 文件。
10. 服务器完成 ASR 和 Agent 处理，返回回答。
11. ESP32-S3 解析响应中的文本，并在 LCD 显示。
12. 用户再次按下按键，可以继续当前唤醒会话中的下一轮交互。
13. 如果等待语音超时或录音失败，当前交互循环退出，设备恢复唤醒检测。

# 七、设备使用说明

## 7.1 使用前准备

1. 确认 ESP32-S3、麦克风、LCD 和按键接线正确。
2. 确认设备电源连接正常。
3. 确保使用环境存在可用的 Wi-Fi 网络。
4. 确认云端 Agent 服务能够正常访问。
5. 检查麦克风没有被遮挡，按键能够正常按下和弹起。

## 7.2 正常使用步骤

**步骤一：设备上电**

连接电源，等待 ESP32-S3 完成初始化。

系统初始化成功后进入待机状态，开始监听唤醒词。

**步骤二：唤醒设备**

对着麦克风说出：

“你好小智”

WakeNet 检测到唤醒词后，LCD 显示：

“小智已唤醒，请按键”

**步骤三：按键确认**

按下 GPIO9 对应的实体按键。

LCD 显示：

“请开始说话”

此时设备开始执行 VAD 语音检测。

**步骤四：进行语音输入**

对着麦克风说出需要询问的问题。

例如：

“明天广州天气怎么样？”

当 VAD 检测到有效人声后，系统自动开始录音。

**步骤五：等待录音结束**

说完后保持安静，系统检测到连续静音达到设定阈值后自动结束录音。

当前静音结束阈值为 800 ms。

**步骤六：等待云端回答**

系统将录制的 WAV 音频上传至云端，服务器进行语音识别和智能体处理。

根据需要，LCD 可显示上传状态和等待响应状态。

**步骤七：查看回答**

服务器返回回答后，ESP32-S3 将回答文本显示在 LCD 上。

**步骤八：继续交互**

如果需要继续提问，直接再次按下实体按键，开始下一轮语音检测和录音。

如果等待语音超时或录音失败，设备退出当前交互会话，返回唤醒检测状态，需要重新说出唤醒词。

## 7.3 使用注意事项

1. 说话时尽量靠近麦克风，避免距离过远。
2. 尽量避免过强的背景噪声，以提高 VAD 和 ASR 的识别效果。
3. 按键按下后再开始说话，避免错过语音开头。
4. 说完后适当停顿，给 VAD 留出判断静音的时间。
5. 云端交互依赖网络连接，网络异常可能导致请求失败。
6. 当前版本只显示文本回答，不播放服务器返回的 TTS 音频。

# 十、后续功能扩展

3. **交互界面优化：** 增加 LCD 动态状态显示、回答分页和交互动画。
4. **通信优化：** 增加网络异常重试、超时处理和连接状态显示。
5. **交互体验优化：** 完善连续对话、唤醒状态管理和语音输入控制。
