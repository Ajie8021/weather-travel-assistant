# 天气模块使用与协作接口

**负责人：成员 A（天气查询、Open-Meteo 接入、天气 MCP 工具）**  
**适用分支：`feat/weather-module`**

## 1. 模块提供的能力

天气模块负责以下工作：

1. 根据城市名称调用 Open-Meteo 地理编码服务，返回候选城市及经纬度、时区；
2. 根据已确认的城市和日期查询单日天气，并转换为统一的 `WeatherData`；
3. 保留上游缺失字段为 `null`，不使用 `0`、晴天等默认值伪造数据；
4. 通过传统页面接口 `GET /weather` 和 MCP 工具同时提供能力；
5. 统一处理城市不存在、城市歧义、日期越界、超时和天气数据不足等错误。

天气数据源为 Open-Meteo，无需配置 API Key。运行环境需要能够访问：

- `https://geocoding-api.open-meteo.com`
- `https://api.open-meteo.com`

## 2. 本地启动与验证

### 2.1 前置条件

- JDK 21；
- Windows PowerShell；
- 能访问 Open-Meteo；
- Maven Wrapper 已随项目提供，无需单独安装 Maven。

若当前终端未识别 JDK 21，可在**当前 PowerShell 窗口**执行（路径以本机实际 JDK 为准）：

```powershell
$env:JAVA_HOME = "C:\Users\xxyyll\.jdks\ms-21.0.12.1"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
```

### 2.2 执行测试

```powershell
cd backend
.\mvnw.cmd clean test
```

验收标准：输出 `BUILD SUCCESS`，并且测试汇总显示 `Tests run: 10, Failures: 0, Errors: 0`。

### 2.3 启动服务

```powershell
cd backend
.\mvnw.cmd spring-boot:run
```

验收标准：日志中出现以下内容：

```text
Tomcat started on port 8080
Registered tools: 2
Started WeaTravAssistantApplication
```

服务默认地址为 `http://localhost:8080`。使用 `Ctrl + C` 可停止服务。

## 3. 传统页面接口（供 C 的 Thymeleaf 页面使用）

### 3.1 请求

```http
GET /weather?city={city}&date={yyyy-MM-dd}
```

示例日期必须按测试当天调整，且只能是当天至未来 15 天内的日期：

```text
http://localhost:8080/weather?city=Shanghai&date=2026-10-21
```

| 参数 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `city` | String | 是 | 不能为空；存在同名候选时必须补充更具体的地区或国家。 |
| `date` | `yyyy-MM-dd` | 是 | 表示目的地当地日期；范围为当天至未来 15 天。 |

### 3.2 成功时 C 可使用的页面模型

Controller 为 `weather.html` 注入模型属性 `weather`，类型为 `WeatherData`。

| Thymeleaf 表达式 | 含义 | 类型 / 单位 | 可空 |
| --- | --- | --- | --- |
| `${weather.city}` | 确认后的城市名称 | String | 否 |
| `${weather.adminArea}` | 行政区 | String | 是 |
| `${weather.country}` | 国家 | String | 是 |
| `${weather.latitude}` | 纬度 | Double | 否 |
| `${weather.longitude}` | 经度 | Double | 否 |
| `${weather.date}` | 查询日期 | `LocalDate` | 否 |
| `${weather.weatherCode}` | WMO 天气代码 | Integer | 是 |
| `${weather.maxTemp}` | 最高温 | Double，°C | 是 |
| `${weather.minTemp}` | 最低温 | Double，°C | 是 |
| `${weather.precipitationProbability}` | 最大降水概率 | Integer，% | 是 |
| `${weather.precipitation}` | 降水量 | Double，mm | 是 |
| `${weather.windSpeed}` | 最大风速 | Double，km/h | 是 |
| `${weather.source}` | 数据来源 | String，当前为 `Open-Meteo` | 否 |

**空值规则：** 可空字段为 `null` 表示上游没有提供该项数据，C 的页面必须显示“暂无数据”或隐藏该项；不得把 `null` 渲染成 `0`、`0%` 或“晴天”。

### 3.3 失败时 C 可使用的页面模型

统一异常处理器会重新渲染 `weather.html`，并注入：

```text
errorMessage
```

C 需要先判断 `errorMessage` 是否存在并显示友好提示；存在错误时不要读取 `weather.xxx`。表单字段名必须使用 `city`、`date`，日期格式为 `yyyy-MM-dd`。

## 4. MCP 工具接口（供 C 的 MCP Client / Agent 使用）

### 4.1 MCP 服务信息

| 项目 | 值 |
| --- | --- |
| MCP 地址 | `http://localhost:8080/mcp` |
| HTTP 方法 | `POST` |
| 模式 | Stateless（无状态） |
| 已注册工具 | `search_city`、`get_weather` |
| 工具性质 | 只读、无副作用 |

开发阶段仅建议在本机使用该地址；部署到公共网络前，需要由团队增加认证和访问控制。

### 4.2 工具一：`search_city`

**用途：** 根据用户输入检索地点候选。不能根据第一个候选自动选择城市。

输入模式：

```json
{
  "city": "Beijing"
}
```

返回值是 `CityData` 数组；每个候选具备以下字段：

```json
{
  "name": "Beijing",
  "adminArea": "Beijing",
  "country": "China",
  "latitude": 39.9075,
  "longitude": 116.3972,
  "timezone": "Asia/Shanghai"
}
```

调用规则：

1. 没有候选时，向用户说明未找到城市；
2. 有一个候选时，可将完整候选对象用于下一步；
3. 有多个候选时，必须把候选的城市、行政区、国家展示给用户并等待确认；**不得**由 Agent、B 或 C 默认选择其中一个；
4. 用户确认后，原样保留该候选的经纬度和时区，再调用 `get_weather`。

### 4.3 工具二：`get_weather`

**用途：** 获取用户已确认地点在指定日期的标准化单日天气。

输入模式：

```json
{
  "location": {
    "name": "Beijing",
    "adminArea": "Beijing",
    "country": "China",
    "latitude": 39.9075,
    "longitude": 116.3972,
    "timezone": "Asia/Shanghai"
  },
  "date": "2026-10-21"
}
```

其中 `location` 必须是 `search_city` 返回并由用户确认的完整对象；`date` 必须为 `YYYY-MM-DD`，且在可预报范围内。

返回值为 `WeatherData`，字段、单位和空值规则与第 3.2 节的 `weather` 模型完全一致。

## 5. 与 B 同学的接口需求（天气规则与行程计划）

### 5.1 B 应如何调用天气模块

B 的计划流程必须先获得标准化天气数据，然后再执行规则判断和计划组装：

```text
TravelRequest(city, date, activityPreference)
        ↓
WeatherService.getWeather(request.getCity(), request.getDate())
        ↓
WeatherData
        ↓
TravelPlanService.generatePlan(request, weather)
        ↓
TravelPlan
```

当前已存在的计划服务签名为：

```java
TravelPlan generatePlan(TravelRequest request, WeatherData weather)
```

天气服务提供的 Java 调用形式为：

```java
WeatherData getWeather(String city, LocalDate date)
List<CityData> searchCityCandidates(String city)
WeatherData getWeather(CityData confirmedCity, LocalDate date)
```

### 5.2 B 必须遵守的约定

1. B 不得直接调用 Open-Meteo，也不得解析 Open-Meteo 原始 JSON；只使用 `WeatherData`。
2. `WeatherData.date` 必须与 `TravelRequest.date` 相同。日期不一致时不应生成行程。
3. `weatherCode` 未知或为 `null` 时，不得推断为晴天。
4. 温度、降水概率、降水量、风速为 `null` 时，B 应跳过依赖该字段的规则判断，并在结果中说明数据不足；不得用 0 替代。
5. `CITY_AMBIGUOUS` 表示地点尚未确认，B 不得继续生成计划；应把候选交给上层与用户确认。
6. B 的 `TravelPlan` 中 `itemsToPack`、`warnings` 没有内容时应返回空数组，而不是 `null`。

### 5.3 B 需处理的天气错误语义

| 错误码 | 含义 | B / 上层应采取的动作 |
| --- | --- | --- |
| `INVALID_INPUT` | 城市、日期等输入非法 | 提示用户重新输入。 |
| `CITY_NOT_FOUND` | 未检索到地点 | 请用户补充或修改地点。 |
| `CITY_AMBIGUOUS` | 候选地点不唯一 | 展示候选，等待用户确认。 |
| `OUT_OF_FORECAST_RANGE` | 日期不在可预报范围 | 请用户选择当天至未来 15 天内日期。 |
| `API_TIMEOUT` | 外部服务请求超时 | 提示稍后重试。 |
| `WEATHER_SERVICE_UNAVAILABLE` | 外部服务不可用 | 提示服务暂不可用，不生成伪造计划。 |
| `WEATHER_DATA_INCOMPLETE` | 关键天气数据无法支持查询 | 提示数据不足，不生成无依据的结论。 |

## 6. 与 C 同学的接口需求（页面与 MCP Client）

### 6.1 页面联调要求

1. 页面表单提交地址为 `/weather`，字段名严格为 `city`、`date`。
2. 成功时按第 3.2 节展示 `weather`；失败时优先展示 `errorMessage`。
3. 所有可空天气字段都要处理 `null`，例如：

```html
<span th:text="${weather.maxTemp != null ? weather.maxTemp + ' °C' : '暂无数据'}"></span>
```

4. 不要在浏览器中直接请求 Open-Meteo；天气 API 调用应始终由后端完成。
5. 不要改变 `WeatherController` 的 HTML 页面返回行为。若需要 JavaScript 使用 JSON，应由团队新增并约定一个独立 JSON 接口。

### 6.2 MCP Client / Agent 联调要求

1. Client 连接 `POST http://localhost:8080/mcp`，发现并调用两个工具。
2. 用户只提供城市名时，先调用 `search_city`。
3. 对多个候选必须让用户确认；确认后再调用 `get_weather`。
4. 需要传递完整的 `location` 对象，不能只把城市名字符串传给 `get_weather`。
5. 按第 5.3 节对错误进行用户友好提示；不要将 Java 堆栈或 Open-Meteo 原始响应展示给用户。
