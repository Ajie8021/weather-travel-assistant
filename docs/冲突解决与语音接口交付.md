## 2. 天气冲突提醒模块

### 2.1 职责
消费 `WeatherData` + `TravelPlanDTO`，输出 `WeatherConflictDTO` 列表；不调外部 API、不改行程、不编造天气。结果由 `ConflictStringMapper` 投影为 `TravelPlanDTO.conflicts`（`List<String>`），供 Agent 询问用户后决定是否修改。

### 2.2 冲突类型
| 类型                   | 触发条件                                                  | 级别 | 来源       |
| ---------------------- | --------------------------------------------------------- | ---- | ---------- |
| HEAT                   | maxTemp ≥ 35                                              | WARN | Open-Meteo |
| COLD                   | minTemp ≤ 5                                               | WARN | Open-Meteo |
| WIND                   | windSpeed ≥ 30 km/h                                       | WARN | Open-Meteo |
| RAIN                   | 降水概率 ≥ 50% 或降水量 > 0                               | WARN | Open-Meteo |
| THUNDERSTORM           | WMO 代码 95/96/99                                         | HIGH | Open-Meteo |
| DATA_INCOMPLETE        | 天气为 null 或关键字段缺失                                | WARN | rule       |
| OPENING_HOURS_CONFLICT | openingHours 与 schedule 可解析且计划未完全落在开放时间内 | WARN | AMAP       |

### 2.3 关键约定
- **阈值唯一来源（C-07）：** 35/5/30/50 集中在 `WeatherConflictProperties`，与 B 的 `TravelRuleService` 一致，变更需同步文档。
- **缺失数据策略：** `weather==null` 返回 `DATA_INCOMPLETE`；字段 null 逐项提示；`openingHours` 不可解析跳过；不把 null 当 0/晴天/无风险。
- **时段级判断：** 仅当 schedule 含 `attraction` 且 `category` 含户外关键词时报 RAIN/WIND/THUNDERSTORM；室内景点不误报；雷暴优先于降雨/大风。
- **开放时间语义（C-08）：** 严格包含，计划时段必须完全落在开放时间内，否则报冲突；仅 `HH:mm-HH:mm` 格式可解析时判断。

### 2.4 MCP 工具
`check_weather_conflicts(city, date, plan?)` → `WeatherConflictDTO[]`，只读。

### 2.5 测试
`WeatherConflictServiceTest` 14 个 + `WeatherAlertToolTest` 3 个，覆盖 null、缺字段、四类日级风险、雷暴、多风险、时段级、室内不误报、开放时间、不可解析、空列表、阻塞判断、去重、参数校验。

## 3. 行程编排与冲突确认闭环

### 3.1 流程
生成/修改 → 检测冲突 → 有 WARN/HIGH 时 `needConfirm=true` → 用户确认 → 修改 → 重新检测。**有冲突不自动改；`confirmConflicts=false` 只检测不修改；天气不可用产出 `DATA_INCOMPLETE`。**

### 3.2 接口
| 接口                       | 归属                                        | 行为                                                         |
| -------------------------- | ------------------------------------------- | ------------------------------------------------------------ |
| `POST /api/plans/generate` | 同学 `EnrichedTravelPlanController`（保留） | 生成真实景点/路线；**当前未注入冲突**，`conflicts` 为空数组  |
| `POST /api/plans/modify`   | 本阶段新增                                  | `confirmConflicts=false` 只返回冲突和询问；`true` 才修改并重新检测 |

`/generate` 的冲突检测目前仅在 `TravelPlanOrchestrator.generate(...)` 中可用，未挂 HTTP 入口；若答辩需“生成即提示冲突”，后续将同学 Controller 内部改为调编排器，或新增 `/api/plans/generate-with-conflicts`，需在 C-15 追加决定。

### 3.3 决策
- **C-09** `TravelPlanDTO.conflicts` 为 `List<String>`，用 `ConflictStringMapper` 投影，不改 record。
- **C-10** record 不可变，修改 = 构造新对象。
- **C-11** 编排集中在 `TravelPlanOrchestrator`，Controller 与 Agent 工具共用；生成器通过 `TravelPlanGenerator` 注入，实际为 `EnrichedTravelPlanGenerator` 适配同学服务。
- **C-12** 不改旧 `/plan/generate`、`/weather` HTML 语义。
- **C-13** `confirmConflicts` 控制是否执行修改。
- **C-14** Agent 工具 `check_weather_conflicts` + `modify_travel_plan`；工具层已强制 `confirmConflicts=true`，提示词约束待 C 配置阶段补齐。
- **C-15** 保留同学 `/api/plans/generate`，本阶段只新增 `/api/plans/modify`；生成入口接冲突检测为后续可选增强。
- **C-16** `PlanGenerateRequest` 为同学 record，集成层不改写，按访问器使用。
- **C-17** 统一使用 `dto.ApiResponse`，不保留 `common.ApiResponse`。

## 5. 语音交互接口

### 5.1 接口
`POST /api/voice/chat`，`multipart/form-data`：

| 参数      | 必填 | 说明                                                         |
| --------- | ---- | ------------------------------------------------------------ |
| file      | 是   | WAV/PCM/16kHz/16bit/单声道，≤ `voice.max-audio-bytes`（默认 5MB） |
| sessionId | 否   | 与 Web 共用；为空生成 `voice-<uuid>`                         |
| format    | 否   | `json` 返回 JSON+Base64；默认 `multipart/mixed`              |

严格模式校验 RIFF/WAVE 头、单声道、16kHz、16bit。

### 5.2 响应
- 默认 `multipart/mixed`：`metadata`(JSON) + `audio`(WAV，仅 OK 且合成成功)；
- `format=json` / `Accept: application/json`：`ApiResponse`，音频在 `$.data.audioBase64`。

### 5.3 状态码
`OK` / `INVALID_AUDIO` / `ASR_EMPTY` / `ASR_FAILED` / `AGENT_FAILED` / `TTS_FAILED`。未配模型 Key 时 Agent 返回 FAILED，语音层映射为 `AGENT_FAILED`，属预期，不是语音模块故障。

### 5.4 配置
`voice.provider=mock|dashscope`（默认 mock）；`voice.max-audio-bytes`；`voice.strict-wav-check`；`voice.tts-failure-tolerant`。切 `dashscope` 前必须完成真实 ASR/TTS 实现，否则明确返回 `ASR_FAILED/TTS_FAILED`，不假成功。

### 5.5 决策
- **C-16** 默认 multipart/mixed，同时提供 JSON+Base64；
- **C-17** ASR/TTS 可插拔，mock 默认，未实现抛错；
- **C-18** 复用 `AgentService` 同一 `sessionId`，语音端同样具备天气、景点、交通、冲突确认和修改能力。

### 5.6 测试
`AudioValidatorTest` 5 + `VoiceChatServiceTest` 8 + `VoiceChatControllerTest` 1；冒烟见第 7 节。

### 7.4 语音冒烟

```bash
ffmpeg -f lavfi -i anullsrc=r=16000:cl=mono -t 1 -c:a pcm_s16le smoke.wav
```
```powershell
curl.exe -X POST "http://localhost:8080/api/voice/chat?format=json" -F "file=@smoke.wav" -F "sessionId=esp32s3_user_001"
```
无 Key 预期 `AGENT_FAILED`；有 Key 预期 `OK`。
