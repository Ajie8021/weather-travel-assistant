# 景点与交通接口说明

## 配置

服务端通过环境变量读取高德 Web 服务 Key，禁止把密钥写入仓库：

```powershell
$env:AMAP_WEB_KEY = "你的高德 Web 服务 Key"
```

可选配置：`AMAP_BASE_URL`（默认 `https://restapi.amap.com`）和 `AMAP_TIMEOUT`（默认 `5000` 毫秒）。

未配置 Key 时，景点和路线接口会返回明确错误；不会返回模型编造的景点或路线。

## 景点接口

```http
GET /api/attractions?city=广州&keyword=历史文化&limit=5
GET /api/attractions/{poiId}
```

`keyword` 可使用“历史文化、自然风光、休闲娱乐、美食、亲子”，服务会转换为更有针对性的 POI 关键词。返回的 `poiId`、坐标、地址和来源均来自高德响应；缺失的评分或营业时间保持为 `null`。

## 路线接口

```http
POST /api/routes/plan
Content-Type: application/json

{
  "originPoiId": "起点 POI_ID",
  "destinationPoiId": "终点 POI_ID",
  "transportModes": ["PUBLIC_TRANSPORT", "WALKING", "DRIVING"]
}
```

可选交通方式：`PUBLIC_TRANSPORT`、`DRIVING`、`WALKING`、`CYCLING`。路线距离、时长、摘要和分段信息均来自高德路线服务。

所有新接口采用以下响应格式：

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": "2026-11-04T19:00:00"
}
```

## 完整行程接口与跨模块 DTO

```http
POST /api/plans/generate
Content-Type: application/json

{
  "city": "广州",
  "date": "2026-11-05",
  "preference": "历史文化",
  "budget": 200,
  "transportPreference": "PUBLIC_TRANSPORT"
}
```

响应的 `TravelPlanDTO` 包含 `attractions`、`routes` 和按早/午/晚排列的 `schedule`。`conflicts` 目前为空数组，预留给天气冲突模块填写；系统不会假装已经完成天气风险判断，也不会估算不存在的数据价格。

## MCP 工具

- `search_attractions(city, keyword, limit)`
- `get_attraction_detail(poiId)`
- `plan_transport(originPoiId, destinationPoiId, transportPreference)`

Agent 已限制为使用真实 POI ID 调用详情和路线工具。天气查询与原有行程接口保持不变。

## 验收命令

```powershell
cd backend
./mvnw.cmd clean test
./mvnw.cmd spring-boot:run
```

启动后可使用：

```powershell
Invoke-RestMethod "http://localhost:8080/api/attractions?city=广州&keyword=历史文化&limit=5"
```

从响应中取两个真实 `poiId` 后，再调用路线接口。请勿将示例中的占位 ID 当作真实地点使用。
